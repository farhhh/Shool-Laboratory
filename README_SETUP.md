# Меню научных симуляций

## Установка обновлённой версии

1. Распакуй архив на компьютере.
2. Скопируй **все файлы из архива** в корень GitHub-репозитория — на один уровень с папкой `Simulations` и главным `README.md`.
3. Разреши замену старых версий одноимённых файлов.
4. Не удаляй и не заменяй папку `Simulations` с лабораториями. Главный `README.md` тоже оставь своим; инструкция из этого комплекта называется `README_SETUP.md`. Страница заглушки для партнёров называется `partners.html` (старую `advertising.html`, если она осталась в репозитории, можно удалить отдельно).
5. Загрузи обновлённые файлы в GitHub и нажми **Commit changes**.
6. Netlify увидит новый commit, автоматически запустит `npm run build` и опубликует обновлённый сайт.

Для этого обновления важно заменить как минимум `index.html`, `build-catalog.mjs` и `catalog.json`. Проще и надёжнее скопировать весь комплект из архива, не трогая `Simulations`.

## Что изменилось в меню

- Навигация по предметам теперь находится слева и остаётся под рукой при прокрутке на широком экране.
- Выбор предмета фильтрует каталог по стабильному ID категории; поиск работает вместе с выбранным предметом.
- В шапке всегда доступны ссылки «Поддержать проект» и «Нашли проблему или есть идеи?».
- Блок партнёрства справа стал контрастнее. Его CSS-классы и ссылка нейтрально названы (`partner-*`, `partners.html`), чтобы блок не принимали за стороннюю рекламную сеть блокировщики контента.
- Шапка получила непрозрачный фон, скругления и более мягкую тень, чтобы прокручиваемое содержимое не просвечивало через неё в Firefox.
- На промежуточных ширинах блок партнёрства остаётся справа; на телефоне превращается в горизонтальную карточку. Навигация на телефоне прокручивается горизонтально.
- Предметы «Информатика», «Биология» и «География» видны в навигации заранее с пометкой «скоро». Когда добавится первая симуляция, счётчик обновится автоматически.

## Куда класть симуляции

Сканер `build-catalog.mjs` проходит по папкам первого уровня внутри `Simulations` и находит `.html` файлы, лежащие непосредственно в папке предмета (не во вложенных подпапках). Для `solar_system.html` он ищет рядом:

- `solar_system.png` — превью карточки (необязательно; без него будет тематическая заглушка)
- `solar_system.txt` — название и описание (необязательно)

Пример:

```text
Simulations/
├── Astonomia/
│   ├── solar_system.html
│   ├── solar_system.png
│   └── solar_system.txt
├── Himia/
│   └── atomnaya_laboratoriya.html
├── Physics/
│   ├── opticheskaya_laboratoriya.html
│   └── elektricheskaya_laboratoriya.html
├── Informatics/
├── Biology/
└── Geography/
```

Поддерживаются также русские названия папок `Информатика`, `Биология`, `География`, а также `Informatika`, `Biologia`, `Geografia`. Категория определяется по расположению HTML-файла, а не по тексту TXT.

Первая непустая строка TXT — название, весь текст ниже — описание:

```text
Солнечная система
Исследуй планеты и наблюдай, как меняется их движение. Меняй параметры и проводи собственные эксперименты.
```

Можно использовать расширенный формат:

```text
Название: Солнечная система
Описание: Исследуй планеты и проводи собственные эксперименты.
Теги: космос, планеты, орбиты
Уровень: 7–9 класс
Время: 10–15 минут
```

## Важно: каталог встроен в index.html

`npm run build` теперь не только пересоздаёт `catalog.json`, но и вставляет каталог прямо в `index.html` (между маркерами `<!--CATALOG:START-->` и `<!--CATALOG:END-->`). Не удаляй эти маркеры. Если публикуешь вручную (Netlify Drop / GitHub Pages без сборки), сначала выполни `npm run build` локально и загрузи обновлённые `index.html` и `catalog.json`.

## Как работает обновление

При каждом GitHub commit Netlify запускает команду из `netlify.toml`:

```bash
npm run build
```

Скрипт `build-catalog.mjs` сканирует папку `Simulations` и пересоздаёт `catalog.json`. Главная страница читает этот JSON. Ссылки на лаборатории рассчитываются относительно адреса опубликованного сайта и получают версию текущей сборки, чтобы браузер телефона не открывал старую копию страницы. В `_headers` также отключено длительное кэширование `catalog.json` и HTML-симуляций. Поэтому при добавлении симуляции **не нужно вручную редактировать `index.html`**: достаточно добавить HTML и, по желанию, PNG и TXT в нужную папку предмета, затем отправить изменения в GitHub.

Если публикуешь сайт вручную через Netlify Drop, сначала выполни `npm run build`, а затем загрузи файлы вместе с обновлённым `catalog.json`.

## Временное скрытие до запуска

В `netlify.toml` и `robots.txt` оставлен запрет индексации поисковиками (`noindex`). Это не закрывает сайт паролем: любой, у кого есть ссылка, всё равно может открыть сайт. Для настоящего ограничения доступа нужна отдельная настройка приватности/защиты Netlify. Перед публичным запуском проверь и убери временные правила `X-Robots-Tag` и запрет индексации, если хочешь появиться в поисковых системах.

## Если симуляция не открывается на телефоне

1. Проверь, что в GitHub в папке `Simulations/Предмет/` лежит именно `.html` файл, а не только превью или TXT.
2. Открой сайт по обычному адресу Netlify с `https://`, затем нажми «Открыть симуляцию». Сборка обновляет адреса ссылок и добавляет параметр версии.
3. После обновления сделай полную перезагрузку страницы каталога на телефоне.
4. Если HTML открывается, но внутри пустой экран, проблема уже внутри исходного файла симуляции (его мобильного JavaScript/Canvas), а не в каталоге. Меню не переписывает лаборатории. Для проверки конкретной лаборатории нужно отдельно проверить её HTML на мобильном устройстве.
